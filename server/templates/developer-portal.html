Taxi Mode API
Three calls. That's the whole API.
The simplest way to put an EV to work. Onboard a car, flip the switch, check on it. One API key, three endpoints — clean enough to wire straight into a car's dashboard button.
1

Onboard a car

One call registers the car and its owner. It comes back with a carId. The car stays private — it won't get rides yet.

POST /v1/cars
2

Flip the switch

Send { "active": true } and the car becomes a taxi. Send false and it's a private car again. This is the in-car "Earn" button.

POST /v1/cars/{carId}/taxi-mode
3

Check on it

Get one car or all of them: taxi mode on/off, battery, lifetime trips and earnings, and the ride it's on right now.

GET /v1/cars/{carId}
🔑

One header on every call

Authenticate with your partner key: X-API-Key: tvny_live_xxxx. Each car belongs to the key that created it, so you only ever see your own.

Scopes: onboarding needs fleet:write, the taxi-mode switch needs rides:write, and reading status needs fleet:read.

// Step 1: onboard a car (and its owner)
const res = await fetch('/api/v1/cars', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'X-API-Key': 'tvny_live_xxxx',
  },
  body: JSON.stringify({
    ownerName: 'Ahmed Al Rashid',
    ownerEmail: 'ahmed@example.com',
    make: 'BYD',
    model: 'Atto 3',
    plateNumber: 'DXB-A-12345',
    isElectric: true,
  })
});

const { carId } = await res.json();
// car is onboarded — still private
// Step 2: the one switch — turn taxi mode ON
await fetch(`/api/v1/cars/${carId}/taxi-mode`, {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'X-API-Key': 'tvny_live_xxxx',
  },
  body: JSON.stringify({
    active: true,        // false = back to private
    lat: 25.2048,
    lng: 55.2708,
  })
});

// the car can now receive rides
// Step 3: check status (one car, or all)
const car = await fetch(`/api/v1/cars/${carId}`, {
  headers: { 'X-API-Key': 'tvny_live_xxxx' }
}).then(r => r.json());

// {
//   carId, taxiMode: true,
//   battery: { percent: 78, source: 'manual' },
//   stats: { totalTrips, totalEarnings },
//   currentRide: { pickup, dropoff, fare }
// }

// all your cars:
await fetch('/api/v1/cars', {
  headers: { 'X-API-Key': 'tvny_live_xxxx' }
});
Agent Gateway
Let your AI book real rides
ChatGPT plugins, Alexa skills, in-car assistants — any agent can quote and book Travony rides with five tools: list_service_types, get_quote, book_ride, get_ride_status, cancel_ride. Available as REST (OpenAPI manifest) and as an MCP server at POST /mcp — same API key, same tools. Bookings are idempotent (an Idempotency-Key retried never double-books), every booking carries your agent's identity (X-Agent-Id), fares are always server-computed, and per-key daily spend caps protect you from runaway agents. Ride status changes hit your webhook signed HMAC-SHA256, and completed rides get an Ed25519-signed receipt anyone can verify against /api/partner/v1/agent/public-key. Scopes: pricing:read, rides:read, rides:write. 
// Live fares for a route — no booking created
const quote = await fetch('/api/partner/v1/agent/quote', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'X-API-Key': 'tvny_live_xxxx',
  },
  body: JSON.stringify({
    pickup:  { lat: 25.2048, lng: 55.2708, address: 'Downtown Dubai' },
    dropoff: { lat: 25.2532, lng: 55.3657, address: 'Dubai Airport T1' },
  })
}).then(r => r.json());

// { currency: 'AED', distanceKm: 10.96,
//   options: [{ serviceTypeId, label, fare }, ...] }  // cheapest first
// Book — idempotent. Retrying with the same key replays
// the original booking instead of creating a second ride.
const ride = await fetch('/api/partner/v1/agent/rides', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'X-API-Key': 'tvny_live_xxxx',
    'Idempotency-Key': crypto.randomUUID(),
    'X-Agent-Id': 'my-chatgpt-plugin',   // who is booking
  },
  body: JSON.stringify({
    pickup:  { lat: 25.2048, lng: 55.2708, address: 'Downtown Dubai' },
    dropoff: { lat: 25.2532, lng: 55.3657, address: 'Dubai Airport T1' },
    riderPhone: '+971501234567',   // the human — gets an SMS tracking link
    serviceTypeId: quote.options[0].serviceTypeId,  // optional; defaults to cheapest
  })
}).then(r => r.json());

// { rideId, status: 'pending', fare, currency,   // fare is SERVER-computed
//   pickupOtp, trackingUrl, driver: { name, car, plate, etaMin } }

// later:  GET  /api/partner/v1/agent/rides/:rideId
//         POST /api/partner/v1/agent/rides/:rideId/cancel
// MCP — plug Travony into Claude, ChatGPT or any MCP client.
// Streamable HTTP endpoint, authenticated with your API key:
{
  "mcpServers": {
    "travony": {
      "url": "https://travony.replit.app/mcp",
      "headers": {
        "X-API-Key": "tvny_live_xxxx",
        "X-Agent-Id": "my-assistant"
      }
    }
  }
}

// Bearer auth also works: Authorization: Bearer tvny_live_xxxx
// tools/list → list_service_types, get_quote, book_ride,
//              get_ride_status, cancel_ride
// Register a webhook — ride.accepted / ride.arriving / ride.started /
// ride.completed / ride.cancelled POST to your https URL with retries.
const { secret } = await fetch('/api/partner/v1/agent/webhooks', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', 'X-API-Key': 'tvny_live_xxxx' },
  body: JSON.stringify({ url: 'https://your-agent.example.com/travony-hook' })
}).then(r => r.json());  // secret is shown ONCE — store it

// Verify deliveries (Express example):
app.post('/travony-hook', express.raw({ type: '*/*' }), (req, res) => {
  const [t, v1] = req.headers['x-travony-signature']
    .split(',').map(p => p.split('=')[1]);
  const expected = crypto.createHmac('sha256', secret)
    .update(`${t}.${req.body}`).digest('hex');
  if (expected !== v1) return res.status(403).end();
  // JSON.parse(req.body) → { event, rideId, status, fare, ... }
  res.status(200).end();
});
// Completed rides have a server-signed, independently verifiable receipt
const r = await fetch(`/api/partner/v1/agent/rides/${rideId}/receipt`, {
  headers: { 'X-API-Key': 'tvny_live_xxxx' }
}).then(r => r.json());

// Verify with Node's crypto — no Travony call needed:
const valid = crypto.verify(
  null,                                  // Ed25519
  Buffer.from(r.canonical, 'utf8'),
  crypto.createPublicKey(r.publicKey),   // pin it from /agent/public-key
  Buffer.from(r.signature, 'base64')
);
// r.payload → { rideId, agentId, fare, currency, route, completedAt, blockchainHash }
EV Fleet Onboarding (Advanced)
Full control: the 5-step EV pipeline
Designed for car brands, leasing companies, and fleet operators. Every EV is automatically tagged, verified, and tracked across the charging hub network.
1

Register the fleet owner

The car brand or leasing company creates a fleet_owner account via OTP. One account manages unlimited vehicles.

POST /auth/complete-registration
2

Register each EV

Submit make, model, plate number, and set isElectric: true. The vehicle is tagged in the EV network immediately.

POST /vehicles
3

AI photo verification

Upload front, side, and interior photos. GPT-4o Vision inspects the vehicle and assigns a condition score (1–10). Score 6+ passes automatically — no human needed.

POST /vehicles/verify
4

Driver goes online

The driver (or the vehicle's onboard system) calls the status endpoint to become available for dispatch. Travony's AI immediately starts matching riders.

PATCH /drivers/status
5

EV hub check-in when battery is low

Driver checks into an EV hub. The system shows staging status — charging → ready → departing. Travony holds dispatch until the EV is ready.

POST /openclaw/hubs/{id}/check-in

Partner API Keys
Scope-based access control
Self-serve: any signed-in account can create keys. Each key is granted only the scopes it needs. Grant fleet:read for monitoring, add rides:write to dispatch programmatically. The legacy ev-hubs:read name still works and maps to hubs:read.
Scope What it unlocks Who needs it
fleet:readList and read the cars you onboarded (status, battery, stats, current ride)Fleet operators, EV brands
fleet:writeOnboard cars and their owners under your accountFleet management systems
rides:readRead ride records and lifecycle status for your fleetAnalytics platforms, insurers
rides:writeCreate rides and flip taxi mode on/off programmaticallyBooking platforms, AV systems
hubs:readEV charging hub network — locations, port availability, EV stagingEV manufacturers, charging operators
pricing:readDynamic fare quotes for a pickup/dropoff and vehicle typeBooking apps, aggregators
demand:readEV demand signals and hub demand heatmap dataCity planners, fleet optimizers
Plans & Quotas
Simple, usage-based pricing
Every key starts on Free. Upgrade any time from your account via Stripe Checkout. Each metered call counts against a monthly quota and a per-minute rate limit. Over the rate limit you get 429 with a Retry-After header; over the monthly quota you get 429 QUOTA_EXCEEDED.
