# Travony - Intelligent Mobility Network

## Overview

Travony is an intelligent mobility network that redefines private vehicles as programmable economic assets. It connects riders and vehicle owners through dedicated React Native mobile applications (T Ride / T Driver) and an Express.js backend. The platform facilitates a peer-to-peer model with a 10% service fee, emphasizing intelligent yield and network optimization over traditional ride-hailing. Key capabilities include AI-powered intent-based matching, dynamic pricing, blockchain verification on Polygon Amoy Testnet, and a comprehensive system for global expansion. Travony aims to transform mobility infrastructure by enabling vehicles to operate as self-optimizing economic units within a distributed network.

## System Architecture

### Frontend
The frontend consists of React Native applications for riders and drivers, built with Expo SDK. It features role-based routing, React Navigation for UI flow, and TanStack React Query for server state management. Authentication uses a custom `useAuth` hook with AsyncStorage. The UI is inspired by Careem, supporting light/dark modes (follows the device setting via `useColorScheme`; the NavigationContainer receives a themed nav theme) and using Reanimated for animations. The rider tab bar has 4 visible tabs (Home, Bookings, Network, Profile) — Wallet is a hidden tab route reachable from the profile sidebar, booking sheet, and assistant. Both tab bars are absolute-positioned; screens pad bottom scroll content with the `useTabBarInset()` hook so buttons clear the bar (RN Modal sheets keep `insets.bottom`). Map integrations provide real-time tracking, route visualization, and ETA display. OpenClaw screens include a heatmap overlay, hub cards, and AI prompts, while Pay Me to Go Home offers a "Going Home" mode with transparent premium pricing.

### Backend
The backend is an Express.js application in TypeScript, providing a RESTful API. It uses session-based authentication with token generation and scrypt for password hashing. Data is stored in PostgreSQL via Drizzle ORM, with a schema covering users, drivers, vehicles, rides, payments, and regional configurations. It incorporates AI for driver matching, dynamic pricing, a dispute resolution system (Fare Guardian), and a city launch system for international expansion. Key features include AI Vehicle Verification using GPT-4o Vision, OpenClaw for intelligent mobility hub management, and Intent-Based Mobility for sophisticated driver-rider matching.

### Core Architectural Patterns and Features
-   **Internationalization**: Designed for global operation with support for localized currency, pricing, vehicle types, emergency services, and multi-language communication.
-   **City Launch System**: Includes a remote city launch framework with phased rollouts, comprehensive driver onboarding, Driver Trust Protection, and a City Champion program.
-   **City Testing Framework**: Implements a trust-first rollout with systematic testing, including `Launch Mode Progression`, a `Test Checklist System`, a `Founding Driver Program`, and `Driver Feedback Collection`.
-   **Admin Dashboard**: A web-based interface for real-time statistics, management of users, rides, cities, disputes, verification queues, and analytics.
-   **OpenClaw - AI-Powered Hub & Hotspot System**: Transforms high-activity areas into community gathering points using AI for hotspot detection, hub recommendations, and carpool matching. It includes a `CommunityPrestigeService` for ranking participation.
-   **EV Hub Intelligence Layer**: 8 hubs designated as EV charging hubs (malls, airports, marinas) with `is_ev_hub`, `total_charging_ports`, `available_ports` fields. EV staging status (charging/ready/departing) tracked per check-in via `hubCheckIns.evStagingStatus`. EV demand signals logged to `ev_demand_signals` table per EV-preferred ride. Driver check-in at EV hub prompts EV staging modal. Hub Detail screen has an EV tab. Fleet operators can read `/api/openclaw/ev-demand-signals`. EV hub map listing at `/api/openclaw/hubs/ev-hubs`. Per-hub EV status panel at `/api/openclaw/hubs/:id/ev-status`.
-   **Pay Me to Go Home (PMGTH)**: Allows drivers to specify a destination and receive direction-compatible rides with premium pricing, featuring abuse prevention mechanisms.
-   **Crypto Payment System**: Integrates abstracted crypto payments using USDT on Polygon Amoy Testnet with a smart escrow system. Transactions are handled in local currencies for users while the backend manages crypto.
-   **Intent-Based Mobility (IBM)**: Matches drivers and riders based on multi-dimensional intent vectors, utilizing a `City Brain` for zone-level flow modeling and dynamic adjustments. Includes `Anti-Gaming Controls` for platform integrity.
-   **Production Resilience Architecture**: Features an `AppError` class hierarchy for structured error handling, and resilience patterns like `retry<T>()` with exponential backoff and a `CircuitBreaker` class for external service integrations.
-   **Ride Event Sourcing**: Utilizes an immutable `ride_event_log` for a complete audit trail of the ride lifecycle, supporting dispute resolution and temporal queries.
-   **Transactional Email System**: Manages email notifications via an email queue with retry logic, using HTML and plain text templates for deliverability.
-   **Coffee Delivery System**: Integrated coffee ordering with three modes (Order for delivery, Buy for pickup, Gift to send to others). Riders access via a floating coffee icon on the home screen. Drivers see available coffee orders and can accept/fulfill them through a dedicated Coffee Orders screen. Menu includes Gulf-region drinks (Karak Tea, Arabic Coffee, Turkish Coffee) alongside standard cafe offerings. Backend routes in `server/coffeeRoutes.ts`, schema in `coffee_orders` table.
-   **Hub Browse System**: When no hubs are nearby, the OpenClaw screen automatically shows a browse-all view grouped by country (UAE, KSA, Kuwait, Bahrain) and city with 44 hubs across 11 cities. Browse endpoint at `/api/openclaw/hubs/browse`.
-   **Trust-First Framework**: Ensures transparency and fairness through an auto-rematch system, rider compensation credits, transparent driver pay formulas (10% platform commission), and phase-based incentive policies tied to city launch modes.
-   **Free Prayer Rides**: Prayer rides are 100% free — zero fare, zero platform fee, zero driver earnings. Drivers volunteer; completed prayer rides show as a "Prayer Rides · Volunteer" badge on the driver profile (`prayerRideCount` on `/api/drivers/me`).
-   **The Car Ladder (One Ring, One Voice)**: Every driver's car quietly builds toward their next, better vehicle. Deterministic engine in `server/carLadder.ts` (catalog per region, pace-based target selection, 2% additive accrual of driver share per completed ride — idempotent per ride, prayer rides excluded, pausable via admin settings). Driver UI is a single progress ring + one Car Agent sentence in the Vehicle Wallet screen; tapping opens one sheet (target, alternatives, contributions, Claim when qualified). Zero crypto vocabulary driver-facing — enforced by a banned-word wall in the Car Agent honesty guard. Dealer claims page at `/dealer` (admin bearer auth). Landing page Network section shows "Drivers climbing the ladder". Endpoints under `/api/ladder/*`.
-   **Public Network Dashboard**: The landing page has a live "Network" section fed by public `GET /api/network/stats` (20s cache, `server/networkStats.ts`) — privacy-safe aggregates only: drivers/riders online, rides in progress, per-city activity, completed rides, hubs/mosques/EV hubs, coffee orders, on-time arrivals, Polygon transactions, and free prayer ride counts.
-   **Live Broadcasts on the Landing Page**: The main landing page has a public "Live Broadcasts" section (nav "Live") listing all live Travony streams — Twitch broadcasts AND in-app Agora streams — grouped by country and city, with country filter chips and click-to-watch inline players: Twitch via a player.twitch.tv iframe (`parent=location.hostname`), Agora via the lazily-loaded AgoraRTC web SDK joining as audience with a token from public `POST /api/agora/web-viewer-token` (subscriber-only, live agora posts only, 15-min TTL, throwaway `web-<hex>` uid; in `server/agoraStreaming.ts`). Fed by public `GET /api/network/live-streams` (25s cache, in `server/socialRoutes.ts`) — Twitch live status re-derived from the real Twitch API, Agora entries from the DB (`isLive` + `endedAt` null) with `provider`, `postId`, `viewerCount`; exposes only name/avatar/twitchChannel/city/country/startedAt, never contact info or coordinates.
-   **Google Sign-Up on the Landing Page**: The landing page nav has a "Sign up" button that starts the existing `server/googleAuth.ts` OAuth flow (`/api/auth/google/start?role=customer`) with the page itself as the redirect target. On return, the inline end-of-body script stores the session token in localStorage (`travonyWebToken`), strips the auth params from the URL via `history.replaceState`, shows a welcome toast, and validates via `GET /api/auth/me` to show the user's first name in the nav (tap again to sign out). The redirect allowlist in `googleAuth.ts` covers own https domains plus app schemes `exp/exps/travony/travony-rider/travony-driver`.
-   **T Ride AI Assistant Home**: The rider Home tab is a ChatGPT-style AI assistant (`client/screens/AssistantHomeScreen.tsx`) with Reanimated polish — animated hero orb + staggered greeting and a 2-column starter-card grid in the empty state, entrance animations on every message, a "Travony" label row on assistant replies, and a three-dot typing indicator; the bottom suggestion-chip rail appears only after the conversation starts. The classic map home remains as the "MapHome" screen (Map button escape hatch). Backend in `server/assistantRoutes.ts`: `GET /api/assistant/home` (deterministic greeting + adaptive chips + activeRideId), `POST /api/assistant/message` (keyword parse → LLM parse fallback → deterministic executor returning `{reply, card, intent}`), `POST /api/assistant/event` (accept/decline logging to `assistant_interactions` for chip personalization; intents validated against a closed set). The LLM only parses intent and phrases replies — an honesty guard rejects any LLM reply containing digits or crypto vocabulary; all numbers come from deterministic server code. Interactive cards (`client/components/assistant/AssistantCards.tsx`): booking (compact quote → expandable breakdown + cash/wallet toggle → explicit Confirm hitting existing `POST /api/rides`), live ride (polls, Lite Mode-aware), places, wallet, trips, coffee, prayer, arrivals — each deep-linking to existing screens. SelectLocation and Invoice "Book Again" hand off to the assistant via Home route params.
-   **Trending & Search (Travony Live)**: Discovery backend in `server/discoveryRoutes.ts` (tables `route_activity`, `trending_cache`, `search_queries` + GIN indexes on users/ride_posts/hubs). Ride completion logs a coarse route (zone → zone, coords rounded to ~1km) fire-and-forget. A 5-min cache refresh scores trending routes (rides + live drivers + open requests, with velocity vs the previous hour), trending posts, and trending search terms. Public `GET /api/trending` reads only the cache — labels are coarse zones with leading street numbers stripped, routes need ≥3 rides/24h to surface, and post meta never includes author names. Auth-gated `GET /api/search` (tsquery prefix + ILIKE fallback across drivers/routes/posts/hubs, returns `queryId`) and `POST /api/search/click` log queries/clicks for the trending-searches loop. Rider/driver UI: Discover screen (`client/screens/DiscoverScreen.tsx`) reached from a search icon in the Network tab header — search bar with debounce, trending search chips, "Hot routes right now" with rising indicators, "Talked about" posts, grouped results.
-   **TikTok-style Guest Mode + Login Sheet**: The app opens straight into the rider (or driver) experience with no onboarding screen — guests can browse Home freely. Gated actions (other tabs, sending an assistant message, booking a ride, going online as a driver) open a TikTok-style login bottom sheet instead (`client/components/auth/LoginSheet.tsx`, orchestrated by `client/hooks/useAuthGate.tsx` — `requireAuth()` returns false and pops the sheet for guests). The sheet offers "Use phone number" (phone → OTP → name, same OTP paste/autofill and "+" country-picker bypass as before) and "Continue with Google" (expo-web-browser → `server/googleAuth.ts` OAuth flow with HMAC-signed state and redirect-scheme allowlist, find-or-create by email, bounces back with a session token), plus terms text and a login/signup footer swap. Location permission is requested quietly on first use.
-   **Social Layer (Follow / Publish / Stream)**: Riders and drivers can follow each other after sharing a ride, publish completed rides to a social feed with an optional caption, and stream rides live on Twitch. Backend in `server/socialRoutes.ts` (tables `user_follows`, `ride_posts`, `users.twitch_channel`); live status is always re-derived from the real Twitch API via `server/twitchClient.ts` (connector app token), never trusted from the DB. Both apps have a 5th "Network" tab, a WebView stream viewer, Twitch channel field in Edit Profile (verified against Twitch on save), follower counts on profiles, a one-tap "Go Live on Twitch" button on active ride screens (marks the ride live on the feed, then deep-links to the Twitch app's broadcast camera via `twitch://broadcast`, falling back to twitch.tv), and publish/follow controls on Ride Details.
-   **TikTok-style Profile (rider + driver)**: Rider Profile tab is a TikTok-style profile (`client/screens/ProfileScreen.tsx`, header hidden): top bar (person-add → Find Friends, share, hamburger → sidebar), avatar with cyan plus badge, @handle, Following|Followers|Likes stats (tappable → FollowList), Edit/Share/QR buttons, bio, "Complete your profile" X/4 cards, grid|liked post tabs (3-col 3:4 tiles → PostComments). Right-slide sidebar (`client/components/profile/ProfileSidebar.tsx`): Balance (rider → WalletTab; driver "Vehicle Wallet" → VehicleWallet), Activity centre, QR code, Settings and privacy. QR sheet (`QRCodeSheet.tsx`): My code (QR of `travony://user/<id>`) / Scan (camera → user preview card → follow). Find Friends screen: debounced user search, Connect Now suggestions, QR, Invite share, Find contacts (expo-contacts → `POST /api/social/find-contacts`, last-9-digit suffix match, list never stored). Rider settings menu moved to `SettingsScreen.tsx`. Driver profile keeps its layout but gains header person-add/menu, Likes stat, sidebar + QR. Backend: `users.bio` (80 chars, editable in Edit Profile), `GET /api/social/counts` (+likes/posts/bio/handle), `/my-posts`, `/liked-posts`, `/user-search`, `/users/:id/preview`, `/activity`.
-   **Rewards System (Coins / Gifts / Diamonds)**: TikTok-style rewards tuned for mobility. Coins are bought from the AED wallet (packs, 0.10 AED/coin) or earned in the Earn Hub: daily check-in streak (5→50 coins across a 7-day cycle), 4 daily missions (complete a ride, publish a memory, react to 3 posts, follow someone; 200-coin daily earn cap), and referrals (invitee gets 100 coins on redeem within 7 days of signup; referrer gets 200 when the invitee completes their first ride, plus milestones at 3/10/25 qualified). Gifts (Gulf/mobility catalog — Rose, Karak, Falcon, etc.) are sent with coins on feed ride posts or to the driver from the ride invoice; recipients receive diamonds, cashable to the wallet at 0.05 AED/diamond with a 200-diamond minimum (atomic CTE drain). Backend `server/rewardsRoutes.ts` (tables `reward_accounts`, `reward_transactions` with UNIQUE user+kind+refId idempotency, `gifts_sent`); all balance moves are guarded SQL inside transactions; `qualifyReferralsForRide` hook runs on ride completion. Frontend: `client/screens/RewardsScreen.tsx` (in both profile stacks, opened from the profile sidebar "Rewards" row), `client/components/rewards/GiftSheet.tsx` (gift picker on SocialScreen feed posts + "Send a gift to your driver" on InvoiceScreen).
-   **Self-Learning Social Match Agent**: People-to-people matching behind the Network tab's "Trending creators" / Connect Now suggestions. Deterministic engine in `server/matchAgent.ts`: 8 real social-graph features (mutual follows, shared rides, gift exchanges, engagement overlap, same city, recency, popularity, creator activity) scored with a weighted sum. Suggestions log impressions (feature snapshot, 24h pair dedupe) to `match_signals`; card dismissals POST `/api/match/feedback`. Every 1 hour the agent learns: follows within 48h of an impression are positives, dismissals negatives, stale ignored impressions soft negatives (0.25); weights nudge toward what worked (LR 0.15, clamp [0.05,3], renormalized so total influence is constant), and a new versioned brain row is saved to `match_weights` — only when ≥3 follows and ≥10 samples exist. Claude (claude-sonnet-4-6 via Replit AI Integrations) writes only the plain-language insight per cycle (honesty guard bans crypto vocabulary; deterministic fallback sentence); it never produces scores. `/api/social/suggested-creators` ranks via the engine (popularity fallback on error) and returns a `reason` line shown on creator cards. Status at `GET /api/match/agent/status` (auth).
-   **TikTok-style Network Tab**: `SocialScreen` is a full-screen TikTok-style experience (header hidden) with a custom top bar — LIVE icon left (red dot when streams are live; opens the first stream), three tabs Explore | Following | For You with a Reanimated spring underline, search icon right (opens Discover). `GET /api/social/feed?tab=following|foryou`: Following = self + followed newest-first; For You = network-wide (14-day window, widens when thin) ranked by engagement (reactions/comments/live/photo/caption) with time decay — all deterministic server code. `GET /api/social/suggested-creators` powers TikTok-style "Trending creators" cards (photo-backdrop 230×320 cards with Follow pill and dismiss X on the empty Following tab, compact chips on Explore and as the Following list footer); excludes self and already-followed, ranked by followers + published rides. Explore page interconnects everything: pressable search bar and trending chips deep-link into Discover (`initialQuery` route param seeds the search), Live Now rail, creator rail, Hot routes rows, Talked-about posts (→ comments), and a Ride Memories tile.

## Navigation Map (lean structure — live entertainment first)

Feature flags live in `client/constants/features.ts` (`FEATURES`). Long-tail surfaces (coffee, network hubs, EV, prayer rides, on-time arrivals, pooling, name-your-fare, crypto/USDT, car ladder) are HIDDEN by default — entry points are gated on flags, screens stay registered in navigators so deep links and in-flight flows never crash, and the backend is untouched. Re-enabling a feature is a one-line flag flip.

### T Ride (rider) — tabs: Home · Movements · Network · Profile (+ hidden Wallet route)
- **Home tab (HomeStack)** — anchor is `Home` (HookFeedScreen, TikTok-style driver discovery feed: Nearby|Following, per-card Book / Go Live / share / reviews, persistent "Book a ride" pill above the tab bar). Booking is one tap away: Book pill / card Book / top-bar AI button → `AssistantHome` (AI booking surface); its "Map" button → `MapHome` (classic map + BookingBottomSheet). Ride flow: SelectLocation → ConfirmRide → ActiveRide → Rating → Invoice. `GoLive` is the rider stream screen. Long-tail routes stay registered but unreferenced when flags are off: OpenClaw, HubDetail, Coffee, ScheduledArrivals, PrayerRides.
- **Movements tab** — Bookings list → RideDetails.
- **Network tab** — Social feed (Explore|Following|ForYou, LIVE rail) → AgoraStreamViewer, Memories, PostComments, Discover, HubDetail.
- **Profile tab** — TikTok-style profile; sidebar reaches Wallet, Settings, Rewards, etc.

### T Driver — tabs: Home · Earnings · History · Network · Profile
- **Home tab** — two hero actions: the online toggle and Go Live (nudge card appears on going online; Go Live request cards come from viewers). Active/incoming ride card is front and center. "Go here next" earnings nudge stays. Hub/EV/coffee quick actions and prayer-pause banner are flag-gated off.
- **Earnings tab** (titled "Earnings", was "Yield") — balance, stats, Vehicle Wallet, transactions; the USDT Crypto Yield card is flag-gated.
- **Profile tab** — secondary/long-tail features live here (~20 screens: TravonyAI, RideTruth, Rewards, etc.).

### Dead-end rules
Every screen is ≤2 taps from a tab; empty states always offer an action (feed empty state still shows the Book pill; gated screens are unreachable rather than broken).

## Design System (one system, TikTok-level fit and finish)

All tokens live in `client/constants/theme.ts` — never use ad-hoc values in screens:
- **Color roles**: `Colors.light` / `Colors.dark` semantic roles (primary, backgrounds, text tiers, error/warning/success, card, overlay) plus brand constants (`travonyGreen`, `liveRed`, `travonyGold`).
- **Type scale**: `Typography` — named keys only (h1–h4, body/bodySmall/bodyLarge, small, caption, label, micro/nano + Bold/Heavy/Medium weights). No raw fontSize/fontWeight in screens.
- **Spacing & radii**: `Spacing` (xs 4 → 5xl 48, `inputHeight`, `buttonHeight`) and `BorderRadius` (xs 8 → full).
- **Motion**: `Motion` — durations (fast 150 / base 220 / slow 350 / pulse 900), the shared press spring (`Motion.spring`, `Motion.pressScale`). One motion language: press feedback, transitions, and the live-badge pulse all use these.
- **Interaction opacities**: `Opacity` (pressed 0.85, disabled 0.5).
- **Glass**: `Glass` — the dark glassmorphic overlay treatment for live surfaces (chip/scrim/scrimHeavy backgrounds, on-glass text/border/fill). Go Live, stream viewer, stream overlays, and the hook feed all draw overlay chrome from this one set.

Components:
- `Button` (`client/components/Button.tsx`) — variants `primary|secondary|ghost|danger`, sizes `md|sm`, built-in `loading` spinner and disabled treatment, shared press spring.
- `StateViews` (`client/components/StateViews.tsx`) — `EmptyState` / `ErrorState`: icon + headline + one supporting line + optional single action; use these instead of raw error text or bare spinners (supports `onDark` for video surfaces).
- `SkeletonLoader` — skeletons for home surfaces.
- Live overlays (`client/components/stream/StreamOverlays.tsx`) — LiveBadge (pulsing dot on `Motion.duration.pulse`), ViewerCountChip, gift layer, ShopTheLook card; all on `Glass` tokens.
